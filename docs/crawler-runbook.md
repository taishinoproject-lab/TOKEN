# 自動収集の手順書（週1回の定期実行用）

作成日: 2026-10-07（T-301〜T-303）
関連: [decisions.md](./decisions.md) D-006 / [data-model.md](./data-model.md) §7・§8・§12 / [venue-selection.md](./venue-selection.md)

この手順書は、週1回起動される Claude Code のセッションが、**この文書だけを読んで**展覧会データの更新案を作れるように書いている。
APIキーは使わない。ページの取得と引用の照合は決定的なスクリプトが行い、本文を読んでデータにするのはセッション自身（AI）が行う。

---

## 0. 守ること（最優先）

1. **推測で書かない。** 会期・展示期間・展示室・料金・出品物は、取得したページの本文に書かれていることだけをデータにする。分からない値は書かない（項目を省くか `null`）。
2. **すべての事実に、原文どおりの引用（`sources[].quote`）を付ける。** 引用は、スナップショット（`crawl/snapshots/`）の本文からそのまま写す。要約・言い換え・補完をしない。
3. **照合できない項目は採用しない。** `npm run crawl:verify` が通らない引用は、引用を直すか、その項目をデータから外して「要確認」に書く。
4. **IDを変えない。** 既存の展覧会の題名が変わっても、`id` はそのまま（URLになるため）。
5. **刀匠・刀剣を推測で結び付けない。** `smith_id` / `sword_id` は、既存のIDで、名前（または `aliases`）が本文の表記と一致し、国や流派も矛盾しない場合だけ付ける。迷ったら付けずに `label` だけにして、「要確認」に書く。新しい刀匠・刀剣のデータは作らない。
6. **画像を扱わない。** チラシや作品の画像を保存・埋め込みしない。リンクだけ（D-003、D-007）。
7. **他社の作品とのコラボ企画は掲載しない**（D-009、D-012-4）。刀剣の展示情報に限る。
8. **型（`src/lib/schema.ts`）とデータ設計を変えない。** 必要だと思ったら「要確認」に書く。
9. **PR を作るか、どのブランチに push するかは、セッションの指示に従う。** 指示のない操作（他のブランチへの push、マージ）はしない。

## 1. 全体の流れ

```
npm ci
npm run crawl:fetch        # ① 巡回：本文を crawl/snapshots/ に保存し、変化を crawl/changes.json に出す
（AI が読む）              # ② 抽出：変化のあったページを読み、data/exhibitions.json を更新する
npm run crawl:verify       # ③ 照合：引用が本文に実在するかを確認する
npm run lint && npm test && npm run build   # ④ 通常の検査（データ検証は build に含まれる）
npm run crawl:report       # ⑤ 報告：crawl/report.md に追加・変更点と引用・元URLを書き出す
git add / commit / push    # ⑥ 人の確認へ
```

### 各ファイルの役割

| ファイル | 内容 | コミットするか |
|---|---|---|
| `crawl/targets.json` | 巡回先（館ID・URL・種類・メモ）、User-Agent、間隔、1館あたりの上限 | する |
| `crawl/snapshots/{館ID}/*.txt` | 取得したページの本文テキスト（引用の照合元） | する（翌週の比較と、PR の確認に使う） |
| `crawl/snapshots/manifest.json` | URL とスナップショットのファイルの対応、取得日、本文が変わった日 | する |
| `crawl/changes.json` | 今回の巡回の結果（新規・変化あり・変化なし・失敗・見送り、増えた行・消えた行） | する |
| `crawl/report.md` | PR の本文用の要約。自動生成部分と、手で書く「要確認」 | する |

## 2. 巡回（`npm run crawl:fetch`）

- 実行すると、`crawl/targets.json` のすべての巡回先を順に取得する。1館だけなら `npm run crawl:fetch -- --venue tnm`。
- 礼儀正しい巡回のための決まり（スクリプトが自動で守る）:
  - 館（オリジン）ごとに `robots.txt` を取得して従う。404 などは「robots.txt なし」としてすべて許可、5xx や通信エラーのときはその館を取得しない。`Crawl-delay` があればそれに従う。
  - リクエストの間隔は `request_interval_ms`（2秒）以上空ける。
  - User-Agent は `TOKEN-crawler/0.1 (+https://github.com/taishinoproject-lab/token)`。
  - 1館あたり `max_pages_per_venue`（8ページ）まで。
- 本文の抽出は決定的（同じページからは同じテキスト）。HTML のコメント、script / style、ルビの読み（rt）は除く。PDF は unpdf でテキストにする。JSON は「キー: 値」の行にする。
- 本文が変わったページだけ、スナップショットのファイルが書き換わる。
- 失敗（`error`）があると終了コードが 1 になるが、他のページの結果は保存されている。失敗したページは前回のスナップショットが残るので、そのまま続けてよい。失敗の内容は「要確認」に書く。

### 結果の読み方（`crawl/changes.json`）

- `summary`: 件数。`changed_venues`: 本文が新規・変化した館。
- `pages[].status`: `new`（初回）/ `changed` / `unchanged` / `error` / `skipped`（robots.txt で禁止、上限超え）。
- `pages[].added` / `removed`: 増えた行・消えた行（先頭200行まで）。**ここだけで判断せず、スナップショットの全文を読む。**

**全館が `unchanged` なら、②〜⑤は不要。** 「変化なし」とだけ報告して終わる（スナップショットのファイルは変わらないが、`manifest.json` の取得日と `changes.json` は更新されるので、指示があればコミットする）。

## 3. 抽出（AI が行う）

### 3.1 何を読むか

1. `crawl/changes.json` で `new` / `changed` のページを確かめる。
2. そのページのスナップショット（`crawl/snapshots/{館ID}/…txt`）を**全文**読む。
3. `data/exhibitions.json` の、その館（`venue_id`）の展覧会をすべて読む。刀剣・刀匠の参照のため、`data/swords.json` と `data/smiths.json` も読む。

### 3.2 登録するもの・しないもの

- 登録する: **刀剣が主題の展覧会・展示**（刀剣の企画展・特別展、刀剣室の展示替え、草薙館の月替わりの刀剣展、現代刀の展覧会など）。
- 登録しない: 刀剣が主題でない展示（屏風、能面、文書などのコーナー展）。他社の漫画・ゲームとのコラボ企画（同時開催でも、その部分は題名・出品リストに入れない）。体験講座・奉納行事などの催し。
- すでに会期が終わった展覧会は、新しく追加しない。既存の展覧会は、終わっていても削除しない（削除はオーナーが判断する）。

### 3.3 既存の展覧会を照合する

その館の既存の展覧会1件ごとに、本文と比べて次のどれかにする。

| 結果 | すること |
|---|---|
| 会期・題名などが本文と一致した | 根拠の引用を `sources` に足し、`verified_at` を今日に、`confidence` を `"confirmed"` にする |
| 本文と違っていた | 本文のとおりに直し、引用を足す。直した点を報告に書く（`crawl:report` が自動で一覧にする） |
| 本文に情報がない（まだ発表されていない、ページから消えた） | 値は変えない。`confidence` は `"unverified"` のまま（`confirmed` だったものを下げるかは「要確認」に書いて、オーナーに任せる） |

- `confirmed` にする展覧会では、**引用で裏付けられない出品物（`exhibits`）や値を残さない。** 旧データ由来で裏付けのない値は外し、外したものを「要確認」に書く。
- 題名は本文の表記に合わせる（「（仮題）」「(仮称)」も含める）。題名が変わっても `id` は変えない。

### 3.4 新しい展覧会を追加する

`data/exhibitions.json` の形式（data-model.md §7）に従う。

```json
{
  "id": "2026-atsuta-jingu-muramasa",
  "title": "村正",
  "venue_id": "atsuta-jingu",
  "room": "剣の宝庫 草薙館",
  "start_date": "2026-10-28",
  "end_date": "2026-11-23",
  "official_url": "https://www.atsutajingu.or.jp/houmotukan_kusanagi/schedule/index02.html",
  "periods": [],
  "exhibits": [],
  "sources": [
    {
      "url": "https://www.atsutajingu.or.jp/houmotukan_kusanagi/schedule/index02.html",
      "title": "熱田神宮 草薙館 年間スケジュール",
      "retrieved_at": "2026-10-07",
      "quote": "令和8年10月28日～11月23日 村正"
    }
  ],
  "verified_at": "2026-10-07",
  "confidence": "confirmed"
}
```

- `id`: `開始年-館ID-英字`（英小文字・数字・ハイフンのみ）。題名をローマ字にした短い語にする。既存と重複させない。
- 日付: 和暦（令和8年＝2026年、令和9年＝2027年）を西暦の `YYYY-MM-DD` に直す。年が省略された終了日（例: 「令和9年1月1日～1月25日」の「1月25日」）は、開始日と同じ年として読み、開始日より前の日付になる場合だけ翌年とする。
- `official_url`: その展覧会の公式ページ。個別ページがなければ、会期が載っている館のページ。
- `room`: 本文にある展示室名だけ。
- `admission`: 本文にある一般料金だけ（例: `"一般 1,200円"`）。展覧会ごとの料金が書かれていない場合は省く。
- `periods`: 前期・後期などの区分が本文にある場合だけ。展示期間が会期の外にはみ出さないこと。
- `exhibits[].label`: 出品目録の表記どおり（例: `"重文 太刀 古青江貞次"`）。行をまたぐ表は、指定・名称・作者を空白でつなぐ。`period_ids` は、作品ごとの展示期間が本文にある場合だけ。
- 刀剣・刀匠の参照は 0. の 5 のとおり。リンクしない行も `label` だけで登録してよい。
- 展覧会が中止・延期と書かれていれば `status` を付ける。

### 3.5 引用（`sources[].quote`）の書き方

- **スナップショットの本文から、連続した文字列をそのまま写す。** 改行は空白1つにしてよい（照合のときに、空白・改行・全角半角・波ダッシュの字形の違いは無視される）。漢字・かな・数字・記号の違いは無視されない（旧字体を新字体にしない）。
- 1つの引用で、**事実と、それがどの展覧会のことかの両方**が分かるようにする。例: 会期なら「令和8年12月5日（土曜日）～令和9年2月14日（日曜日） 冬季特別展「古備前―刀剣王国の黎明（仮題）」」のように、日付と展覧会名を含む範囲を引く。料金が展覧会ごとの節にある場合は、節の見出しから料金まで、または料金から次の節の見出しまでを引く。
- 空白を除いて6文字以上にする（短すぎる引用はエラーになる）。
- 出品物は1行（1作品）ごとに1つの引用を付ける（例: 「重文 太刀 1口 古青江貞次 鎌倉時代・13世紀」）。
- `url` は `crawl/targets.json` の URL と**完全に同じ文字列**にする（照合はこの URL でスナップショットを探す）。`retrieved_at` は今日の日付。`title` は出典の名前（例: 「備前長船刀剣博物館 年間展示予定(2026年度)」）。
- 旧データ由来の、引用のない出典（`"旧データ（src/data）に記載のURL。内容は今回未確認"` など）は、同じ URL に引用付きの出典を足した場合は外してよい。

## 4. 検証

次をすべて実行し、すべて成功させる。

```
npm run crawl:verify   # 引用の照合（照合できない引用が1件でもあれば失敗）
npm run lint
npm test
npm run build          # データ検証（scripts/validate-data.ts）を含む
```

- `crawl:verify` が失敗したら、表示された引用をスナップショットの本文と見比べて、写し間違いを直す。本文にない内容なら、その項目をデータから外す（「要確認」へ）。
- `build` のデータ検証のエラー（参照切れ、日付の前後、展示期間のはみ出しなど）は必ず直す。警告は増やさないようにする。

## 5. 報告（`crawl/report.md`）

1. `npm run crawl:report` を実行する。基準（既定は `origin/main`）と比べた、追加・変更・削除の一覧と、根拠の引用・元URLが、`crawl/report.md` の自動生成部分（`<!-- crawl:report:auto:start -->` 〜 `end`）に書き出される。基準は、PR の向き先（作業ブランチの分岐元）にする。`origin/main` 以外なら `npm run crawl:report -- --base origin/<ブランチ名>`（先に `git fetch origin <ブランチ名>` を実行する）。
2. 自動生成部分の外に、手で次を書く（再実行しても消えない）。
   - **要確認**: 照合できずに採用しなかった項目、外した旧データの値、刀匠・刀剣のリンクを迷ったもの、取得に失敗したページ、ページの構造が変わった館など。
   - 巡回先を追加・変更した場合は、その理由。
3. この報告を、そのまま PR の本文に使えるようにする。

## 6. コミットと push

- 変更するファイル: `data/exhibitions.json`、`crawl/`（snapshots・changes.json・report.md、必要なら targets.json）。**それ以外は変更しない。**
- コミットメッセージは日本語で、先頭に `data:` を付ける（例: `data: 自動収集 2026-10-14（熱田神宮・備前長船）`）。
- push 先はセッションの指示に従う（指示がなければ push せず、報告だけをする）。

## 7. 巡回先の管理（`crawl/targets.json`）

- 巡回先を足すときは、**必ず対象館の公式ドメイン（D-006 で許可された15館のドメイン）のページだけ**にする。まとめサイトや観光サイトは巡回先にしない（出典にもしない）。
- 足す前に、ページを1回取得して、本文に展覧会情報があること（JavaScript で描画していないこと）を確かめる。本文が空のページは `error` になる。
- `note` に、そのページに何が載っているか、注意点を書く。
- `expect_text` に、そのページの本文に必ずある短い文字列（ページの見出しなど）を書く。本文にこの文字列がなければ、別の言語の版やエラーページが返ったとみなして `error` にし、前回のスナップショットを残す。
- URL を変えると、スナップショットのファイル名も変わる（新しいページとして `new` になる）。データの `sources[].url` も同じ文字列に直す。
- 1館あたり8ページまで。会期が終わった展示の個別ページは外してよい。
